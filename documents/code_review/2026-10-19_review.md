*Branch `zhr_edits`, 2026-10-19. Reviewed against `main` at `8a1d9ba`.*

Reid's pipeline is in good shape. Re-running it reproduces every committed output byte for byte, and an independent re-derivation from the raw exports — written without reusing any of his code — agrees with his transect, site, basin and Puget Sound tables. The problems found are at the edges: how the launcher finds R, a datasheet change that the pivot turned into fake zeros, some rounding, and how the trend metric aggregates. ## 1. The launcher, and why it crashed

**The crash.** `Documents\.Renviron` sets `R_LIBS_USER="C:/R/win-library/4.5"`. The old launcher looked for R on the PATH and then under `C:\Program Files\R`, where the only R is 4.1.3. Your everyday R 4.5.1 is a per-user install in `AppData\Local\Programs\R`, which the launcher never looked in. R 4.1.3 then read the same `.Renviron`, loaded packages compiled for R 4.5, and `digest.dll` asked for an R 4.5 entry point R 4.1 does not have. This would happen on any machine where R versions and libraries do not line up, so it is the general fragility you wanted gone.

**The fix.** The new `run_data_interpreter.bat`:

1. reads `gui/launcher/runtime.cfg`, which pins R 4.6.1, the installer's SHA-256 and a CRAN snapshot date (2026-10-01);
2. on first run (`gui/launcher/setup_runtime.ps1`) downloads the official CRAN installer, refuses it unless the checksum matches, and installs it silently into `%LOCALAPPDATA%\CCR\understory_kelp_indicator\R-4.6.1`. That needs no admin rights and adds no icons or file associations, and RStudio's "current R" is left alone. It then installs the 54 packages the app needs, as Windows binaries from the dated snapshot (`install_packages.R`);
3. runs the app with that R, that library only, and empty stand-ins for `.Renviron`/`.Rprofile`. The step scripts the app launches inherit the same isolation.

It lives outside Dropbox deliberately: it is about 310 MB and 8,400 files (about 140 MB to download), which would otherwise sync to everyone sharing the folder. `--repair` rebuilds it, and deleting the folder resets it. The private R shows in Apps & Features as "R for Windows 4.6.1". If exactly that version is already installed, it is reused rather than installed twice, because two installs of one version would fight over a single Apps & Features entry. `Create Desktop Shortcut.bat` adds a desktop icon.

**Tested on your machine** (the one with the bad `.Renviron`): the first run downloaded, verified (the MD5 also matches CRAN's published fingerprint) and installed R, installed the packages, and started the app, in about two minutes. The second start took about two seconds. After the install, the registry's current R is still 4.5.1. Closing the browser tab shut the app down and closed the launcher. Steps 1–3 then ran from the GUI under the private R: the step 1–2 tables are byte-identical to the same steps run with your R 4.5.1, and step 3 wrote the 320-figure default set (about 25 minutes at 300 dpi).

**Logos.** Shiny serves `gui/www/` only when the app is started as a folder (`runApp("gui")`, or RStudio's Run App button, which is likely what Reid uses). Selecting all of `app.R` and running it calls `shinyApp()` directly, which serves no `www/`, so the browser showed the alt text. `app.R` now registers the folder itself (`addResourcePath`), so the logos load either way.

## 2. Data wrangling

### What was verified

* **Reproducibility.** `rc_full_data_clean.R` → `metrics_across_scale.R` re-run from `main` reproduces all four committed csvs exactly.
* **Independent re-derivation.** Transect algae counts (distance-scaled, giant kelp/feather boa summed), UPC proportions, then site, basin and Puget Sound means/SD/variances were rebuilt from the raw files with separate code. Every value agrees, apart from the rounding effects below.
* **Structure.** One row per transect survey (899), unique keys, metadata consistent. Cover, relief and substrate each sum to 1 per transect. Superlayer does not, and should not: most points have no superlayer.

### Found and fixed

| issue | effect | fix |
|---|---|---|
| **Categories missing from a year's datasheet became 0.** UPC added the superlayer (2022), Clay (2023) and Acid Weed cover and superlayer (2024); invert and fish added species in 2022–23. `pivot_wider(values_fill = 0)` filled those years with zeros. | 1,086 fake UPC zeros (e.g. cover/acid weed is 0 in every 2021–23 transect), 696 invert, 2,483 fish. In the figures this showed acid weed "appearing" in 2024; the old percent-change figures include these. | `complete_on_sheet()`: 0 = looked for and not found, NA = not on that survey's datasheet. The algae datasheet never changed, so algae values are unaffected. |
| Scaled counts **truncated**: `as.integer(amount/distance*30)` | biased every scaled count down (338 individuals of 200,243), and floating point turned whole numbers like 56/16.8×30 = 100 into 99 (4 cases) | `round(amount*30/distance)` (algae and invert) |
| **Rounded to 3 decimals at every scale**, with the next scale built from the rounded values | 145 of 854 non-zero site variances became exactly 0; small site means off by up to 8% | full precision in memory; 6 significant figures on write |
| `n_transects` counted rows, not transects the dataset covered | wrong for Cattle Point 2024 (5 algae / 4 UPC transects) and Point Caution 2025 | `n_transects_algae`, `_upc`, `_invert`, `_fish` |
| UPC cover "Mobile Invertebrates" had no recode, so it lost its prefix | latent (Northern Coast only), but would have vanished silently | recoded to `cv_mobile_inverts`; unknown future classes take their category's prefix and are named in the log |
| Invert and fish stopped at the cleaned table | not available above the transect scale | carried to site, basin and Puget Sound like algae and UPC |
| Densities only from the site scale up | no transect table in density units for NMDS/GLMM | `results/metrics_transect_scale.csv` (individuals m⁻²; UPC proportions) |

### Still true of the data, and worth knowing before the funder meeting

* **Site composition changes from year to year.** Central Puget Sound averages 3 sites in 2021, 8 in 2022, 13 in 2023 and 16 in 2024–25; Admiralty Inlet's 2022 "basin" is one site. A basin's density line therefore mixes real change with which sites were surveyed. The figures now print *sites per year* in their subtitle. A balanced-panel option, or a mixed model with a site random effect (the planned GLMMs), is the proper treatment. The temporal trend sidesteps the problem because it compares every site only with its own past.
* **2021 is thin.** It covers 3 inner basins and 5 sites. The Puget Sound 2021 density, and every 2022 trend value, rest on those 5 sites.
* **Brown algae cover is not comparable across 2023/2024.** Before Acid Weed had its own UPC class, those points were presumably logged as Other Brown Algae (and the superlayer equivalent), so brown algae cover drops in 2024 for bookkeeping reasons. Options are in §6.
* **Fish YOY rockfish** were one class in 2022 and species-level from 2023.
* **Fish use transects 1–6 only**, the ones that share rows with the benthic data. Fish are counted on up to 25 transects, and transects 1–6 hold only 30% of the fish individuals counted, so 70% are dropped. That is fine for a one-row-per-transect table, but a fish-only site average should use all of them.
* The **per-dataset cleaning scripts** (`rc_algae_data_clean.R` etc.) are a second, older pipeline the app does not use. Their outputs in `results/` (`reef_check_*_cleaned.csv`) still carry the truncation and zero-fill issues. Suggest archiving them.

## 3. The temporal trend metric (issue #2)

### The previous implementation

`algae_temporal_density.R` computed 2025 against a baseline built by pooling the raw transects of 2021–2024.

* **Structure.** The LaTeX defines the baseline as the mean of the annual site densities. Pooling transects is the same thing only when every year has six transects. It differs at Cattle Point (2024 had five), by up to 54 percentage points.
* **Only 2025.** One number per site, not a series. (A small thing too: its `setwd("../")` is commented out, so it fails when run from `code/`, unlike every other script.)
* **Aggregation.** Basin values were the arithmetic mean of site ratios, and that is the substantive problem:
  * ratios are heavy-tailed: 2025 site values run from 0 to 2,550% (15,600% across all years). One site with a near-zero baseline dominates a basin mean;
  * dropping Inf (newly appeared) while keeping 0 (lost) is asymmetric and drags the mean down;
  * the result can contradict the basin's own densities. San Juan Islands winged kelp: mean of site ratios **521%**, while the basin's density across the same sites is **102%** of baseline.
* **The GUI's "Percentage" scale was a different metric.** It was each year's basin mean against the mean of all *other* years, including later ones. That compares 2022 with 2025, which no trend indicator should do. It has been retired.

### What it does now (`code/temporal_trend.R`, run as part of step 2)

**Site scale.** For every site, category and year *t* with at least one earlier survey:

K = 100 × D(t) / mean(D(t−1), …, D(t−5))

where D is the site's annual mean (the site table's `_avg`) and the baseline uses whichever of the five preceding years the site was surveyed. So far a 2025 value has at most four baseline years; `n_baseline_years` records how many each value had.

**The edge cases are named, not just computed:**

| status | current | baseline | K stored as |
|---|---|---|---|
| present | > 0 | > 0 | the number |
| lost | 0 | > 0 | 0 — a real decline, kept |
| new | > 0 | 0 | NA (was Inf) |
| absent | 0 | 0 | NA (was NaN) — nothing to compare |

**Basin and Puget Sound scales — ratio of the averages** (`trend_pct`):

K(basin) = 100 × mean over sites of D(t) / mean over sites of baseline

This is taken over the sites that have both a current value and a baseline, so a basin is never compared with a different set of its own sites. Lost and new sites simply add their zero to one side; absent sites add nothing to either. Inf and NaN can only arise when a category is new to, or absent from, *every* site in the basin, which is the honest answer. Puget Sound repeats the step over basins, each weighted equally, as the density tables do. In LaTeX, for `temporal_trend_figure.tex` if you adopt it:

```latex
K_{s,b,t} = 100\,
  \frac{\frac{1}{n}\sum_{i \in S_{b,t}} D_{s,i,t}}
       {\frac{1}{n}\sum_{i \in S_{b,t}} \bar{D}^{\,\mathrm{base}}_{s,i,t}},
\qquad S_{b,t} = \text{sites in basin } b \text{ with both a year-}t\text{ value and a baseline}
```

The issue's mean of site ratios is still written beside it (`trend_pct_mean_of_sites`, `trend_pct_mean_of_basins`), together with counts of present, lost, new and absent sites, so the choice stays visible. Where the two disagree in 2025:

## 4. The GUI

**Preview a figure** is now four choices, in your order. They are also the four levels of the folder each figure saves to:

1. **Analysis** — Temporal trend · Average density · Average density with standard deviation. NMDS and GLMM slot in here later.
2. **Scale** — Site · Basin · Puget Sound (Washington-wide too, when the withheld basins were kept).
3. **View** — Species within geography · Species across geography · Species composite within geography.
4. **Data** — Algae, Cover, Relief, Substrate, Superlayer.

A second row then asks only for what that figure still needs: which site (grouped by basin), basin or region; or, for *across*, which species, plus a basin at the site scale, whose sites become the panels. It also holds a **Lock y-axis** switch.

Your instincts on the old layout were right. "Invert to Category" and "Basin and species composites" were views dressed as a scale and a figure type, and "Percentage" was a separate metric in the scale slot. Two combinations are deliberately not offered, and the reasons are written into the code: *across* at the Puget Sound scale (there is only one geography), and an SD band on a *composite* (ten bands on one axis bury each other).

Other changes:

* **Facet titles** put the scientific name on its own line, so "broad-ribbed kelp (*Pleurophycus gardneri*)" no longer runs off its strip. The "n = 2 sites" note now reads "(2 of 3 sites)": it counts sites where the species was recorded at least once, which was being read as the sample size. It moved into the title so it never collides with data.
* **Captions** say what blue, gray and the band are, and that the band is ±1 SD *among sites* (or transects, or basins), not an uncertainty interval. The subtitle gives the units behind each year.
* **The preview is the saved file**: drawn on the export's 12 × 7 in canvas and scaled to the window. Before, it was redrawn at window width and clipped in narrow windows.
* **What to draw** uses the same four choices plus float/lock, counts the files, and writes to `figs/<analysis>/<scale>/<view>/<data type>/`. The default set (basin and Puget Sound scales, everything else ticked) is 320 figures. The site scale is about 1,500 and left for when it's wanted. The 429 old figures (old folder layout, stale values) were removed and the default set regenerated.
* Step 2 now runs both of its scripts, and the log no longer drops a script's last lines.

## 5. How this was checked

* Pipeline outputs from `main` reproduce exactly. An independent re-derivation matches at every scale.
* The fixed pipeline differs from the original only where intended: algae only by the rounding fix, UPC/invert/fish only by the 0→NA cells, and the counts above match the datasheet changes cell for cell.
* Trend values hand-checked. For example, Lowell Point sugar kelp 2025: 1.1333 ÷ mean(2.2778, 1.3972, 0.9417, 1.5778) = 73.2%.
* All 21 valid analysis × scale × view combinations render for all five data types (105 figures, drawn under the private R). The 6 combinations with no honest figure are refused with a reason. Previews were exercised in the browser.
* Launcher first run tested end to end on the machine that crashed; second start, auto-shutdown on closing the tab, and steps 1–3 from the GUI under the private R too. Step 1–2 outputs are byte-identical to R 4.5.1's.
* The withheld-basins path, run into a scratch folder, works: 10 basins, Washington-wide written at both scales, legacy substrate classes carried, Mobile Invertebrates prefixed, compositions still summing to 1.

## 6. Decisions for you

1. **Headline aggregate for the trend.** Ratio of averages (implemented as `trend_pct`) or mean of site ratios (kept alongside)? My recommendation is the former, for the reasons in §3. Either way, `temporal_trend_figure.tex` should say which.
2. **Minimum baseline.** Currently one earlier year is enough. Two would drop the five sites first surveyed in 2024 from the 2025 values (`UKELP_TREND_MIN_BASELINE_YEARS`).
3. **Brown algae and acid weed cover.** Merge them for a consistent series, or report brown algae from 2024 only?
4. **Balanced panel** for the density figures (sites surveyed every year of the window), or leave composition to the GLMMs?
5. **Fish site averages** from all fish transects rather than 1–6?
6. **Housekeeping:** archive the per-dataset cleaning scripts and their outputs; decide whether generated figures belong in git at all (they are most of the repository's size).
